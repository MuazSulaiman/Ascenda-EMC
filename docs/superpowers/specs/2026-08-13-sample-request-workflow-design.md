# Sample Request Workflow — Implementation Plan

**Status:** Draft for review — not yet implemented. Nothing in this document has been built; no schema, files, or navigation changes exist yet. Implementation starts only once this plan is reviewed and the user confirms.

**Decisions locked in during planning** (do not re-litigate these without the user):
- **Samples only.** No "Demo" type, no Old/New (trade-in) tracking, no expected-return-date field. Demos will become a separate device-rotation module later, out of scope here.
- The coordinator/warehouse handoff stays a **manual step, same as Quotations**: no Odoo API/RPC integration. The coordinator downloads an Excel pick sheet, gets it filled in physically at the warehouse, manually creates the delivery in Odoo, then types the resulting Odoo reference back into the app to mark the request Done.
- **No structured serial/batch/warehouse-location capture inside the app.** That data lives only on the printed/downloaded Excel sheet. This was the deliberate fix for the "messy coordinator flow" — the app's job is tracking the *request* lifecycle and producing the pick sheet, not becoming a warehouse inventory system.
- No new "warehouse staff" role. The sales coordinator (existing role, already added to `users.role` by the Quotations migration) does the whole handoff, same as today's manual Excel process.
- No pricing/VAT/totals — sample requests have no monetary math, unlike quotations.
- New: a **manager decision-support insights panel** on the review screen, showing the requesting rep's and the customer's fulfilled (`DONE`) sample history (all-time + this-month, total units, across all reps for the customer view), with an expandable recent-requests list.

---

## Context

Reps currently fill out a shared Excel/VBA workbook (`Sample & Demo Request/EMC_Sample_Demo_Request_Template_23.07.2026.xlsm`) to request samples (and, separately, demos — out of scope here). A `Worksheet_Change` macro explodes each line's quantity into one row per physical unit on a "Warehouse" sheet, which warehouse staff hand-annotate with serial/batch numbers, warehouse name, and location. There's no digital approval trail and no link into Odoo — identical gap to what the Quotations module solved for quotations.

The goal is the same shape as Quotations: move the **request → approval → Odoo handoff** part into Ascenda, while keeping the physical fulfillment (picking, serializing) exactly where it already works today — on paper, at the warehouse — because trying to pull that into structured DB fields is what made earlier thinking about this "messy." The app's scope ends at handing the coordinator a clean pick sheet and recording that Odoo now has the delivery.

This is modeled directly on the existing **Quotations module** (`app_pages/quotation_request.py` / `quotation_review.py` / `quotation_handoff.py` / `quotation_helpers.py`, `migrations/quotations_schema.sql`), reusing its guarded-transaction idiom, revision-snapshot pattern, notification calls, and page structure. Sample Requests get their **own** tables (not reused from `quotation_*`) because the field set is materially different (no pricing, has per-line delivery dates, needs the pick-sheet export) and because keeping domains separate is the established convention (Quotations didn't reuse `request_changes` either, for the same reason).

## Schema (new, additive — nothing existing is altered)

Goes into `init_db_v11.py`'s schema block (fresh-DB path) **and** a new `migrations/sample_requests_schema.sql` (loaded by `db.py::_run_migrations()`, same precedent as `quotations_schema.sql`). No role/enum-type migration needed — `sales coordinator` already exists on `users.role` from the Quotations migration, and (matching the live `quotation_requests` table, which uses a plain `TEXT CHECK` rather than the Postgres enum type an earlier quotations draft considered) status here is also `TEXT CHECK`.

### `sample_requests` (header)

```sql
CREATE TABLE IF NOT EXISTS sample_requests (
    sample_request_id  BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    request_number      TEXT    NOT NULL UNIQUE,      -- e.g. SDR-2026-000001, assigned once at first submit
    customer_id           INTEGER NOT NULL REFERENCES customers(customer_id),
    rep_user_id            INTEGER NOT NULL REFERENCES users(user_id),

    request_date            DATE    NOT NULL DEFAULT CURRENT_DATE,
    remarks                   TEXT,

    status  TEXT NOT NULL DEFAULT 'IN_REVIEW' CHECK (status IN (
                 'IN_REVIEW', 'EDIT_REQUESTED', 'REJECTED', 'APPROVED', 'DONE', 'WITHDRAWN'
             )),
    version  INTEGER NOT NULL DEFAULT 0,               -- optimistic lock, same convention as quotation_requests.version

    submitted_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    submitted_by  INTEGER NOT NULL REFERENCES users(user_id),

    manager_user_id      INTEGER REFERENCES users(user_id),
    manager_decided_at   TIMESTAMPTZ,
    manager_comment       TEXT,

    coordinator_user_id      INTEGER REFERENCES users(user_id),
    coordinator_done_at       TIMESTAMPTZ,
    coordinator_note           TEXT,
    odoo_reference               TEXT,                -- normalized: blank input stored as NULL, never ''

    withdrawn_at       TIMESTAMPTZ,
    withdrawn_by        INTEGER REFERENCES users(user_id),
    withdrawal_reason    TEXT,

    is_deleted   BOOLEAN NOT NULL DEFAULT FALSE,       -- admin-only technical escape hatch, not rep cancellation
    deleted_at    TIMESTAMPTZ,
    deleted_by     INTEGER REFERENCES users(user_id)
);

CREATE UNIQUE INDEX IF NOT EXISTS idx_sr_odoo_ref_unique
    ON sample_requests (odoo_reference) WHERE odoo_reference IS NOT NULL;
```

### `sample_request_lines`

```sql
CREATE TABLE IF NOT EXISTS sample_request_lines (
    line_id            BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    sample_request_id  BIGINT NOT NULL REFERENCES sample_requests(sample_request_id) ON DELETE CASCADE,
    line_no            SMALLINT NOT NULL CHECK (line_no BETWEEN 1 AND 50),
    product_id         TEXT NOT NULL REFERENCES items(product_id),
    quantity           INTEGER NOT NULL CHECK (quantity > 0),
    delivery_date      DATE,
    created_at         TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    UNIQUE (sample_request_id, line_no)
);
```
`quantity` is a whole-unit `INTEGER` (unlike quotations' fractional `NUMERIC`) because sample items are discrete physical units that get exploded 1:1 into pick-sheet rows — there's no fractional-unit case to support. 50-line cap matches the legacy workbook's item grid (rows 11–60).

### `sample_request_revisions` / `sample_request_revision_lines`

Same immutable-snapshot pattern as quotations, minus money fields:

```sql
CREATE TABLE IF NOT EXISTS sample_request_revisions (
    revision_id         BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    sample_request_id   BIGINT NOT NULL REFERENCES sample_requests(sample_request_id) ON DELETE CASCADE,
    revision_no         SMALLINT NOT NULL,
    created_at           TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    created_by            INTEGER NOT NULL REFERENCES users(user_id),
    customer_id            INTEGER NOT NULL REFERENCES customers(customer_id),
    request_date            DATE NOT NULL,
    remarks                   TEXT,
    UNIQUE (sample_request_id, revision_no)
);

CREATE TABLE IF NOT EXISTS sample_request_revision_lines (
    revision_line_id        BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    revision_id              BIGINT NOT NULL REFERENCES sample_request_revisions(revision_id) ON DELETE CASCADE,
    line_no                    SMALLINT NOT NULL,
    product_id                  TEXT NOT NULL REFERENCES items(product_id),
    article_number_snapshot      TEXT,   -- frozen copy of items.article_number at snapshot time
    description_snapshot          TEXT,  -- frozen copy of items.description at snapshot time
    quantity                        INTEGER NOT NULL,
    delivery_date                    DATE
);
```
Revision numbering derives from `version` (same atomic technique as quotations' `resubmit_quotation`), never `MAX(revision_no)+1` — avoids a race under concurrent resubmits.

### `sample_request_status_events`

```sql
CREATE TABLE IF NOT EXISTS sample_request_status_events (
    event_id            BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    sample_request_id   BIGINT NOT NULL REFERENCES sample_requests(sample_request_id) ON DELETE CASCADE,
    event_type          TEXT NOT NULL CHECK (event_type IN (
                             'SUBMITTED', 'RESUBMITTED', 'EDIT_REQUESTED', 'APPROVED',
                             'REJECTED', 'WITHDRAWN', 'RETURNED_FOR_REVISION', 'MARKED_DONE'
                         )),
    actor_user_id       INTEGER NOT NULL REFERENCES users(user_id),
    from_status          TEXT,
    to_status              TEXT NOT NULL,
    comment                  TEXT,
    revision_id               BIGINT REFERENCES sample_request_revisions(revision_id),  -- set only for SUBMITTED/RESUBMITTED
    at_utc                      TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```

### `sample_request_number_counters`

```sql
CREATE TABLE IF NOT EXISTS sample_request_number_counters (
    year     INTEGER PRIMARY KEY,
    last_seq INTEGER NOT NULL DEFAULT 0
);
```
Same atomic upsert as quotations (`ON CONFLICT (year) DO UPDATE SET last_seq = last_seq + 1 RETURNING last_seq`), formatted `f"SDR-{year}-{seq:06d}"` — reusing the `"SDR"` prefix the legacy workbook already reserved (`Settings!FormPrefix`) but never wired up.

### Indexes

```sql
CREATE INDEX IF NOT EXISTS idx_sr_status        ON sample_requests(status);
CREATE INDEX IF NOT EXISTS idx_sr_rep            ON sample_requests(rep_user_id);
CREATE INDEX IF NOT EXISTS idx_sr_customer       ON sample_requests(customer_id);
CREATE INDEX IF NOT EXISTS idx_sr_manager        ON sample_requests(manager_user_id);
CREATE INDEX IF NOT EXISTS idx_sr_coordinator    ON sample_requests(coordinator_user_id);
CREATE INDEX IF NOT EXISTS idx_srl_request       ON sample_request_lines(sample_request_id);
CREATE INDEX IF NOT EXISTS idx_srl_product       ON sample_request_lines(product_id);
CREATE INDEX IF NOT EXISTS idx_srev_request      ON sample_request_revisions(sample_request_id, revision_no);
CREATE INDEX IF NOT EXISTS idx_srse_request      ON sample_request_status_events(sample_request_id, at_utc);
CREATE INDEX IF NOT EXISTS idx_sr_customer_done  ON sample_requests(customer_id, status) WHERE status = 'DONE';
CREATE INDEX IF NOT EXISTS idx_sr_rep_done       ON sample_requests(rep_user_id, status) WHERE status = 'DONE';
```
The last two partial indexes exist specifically to keep the manager-insights aggregate queries fast (they always filter `status='DONE'`).

## New files

#### `app_pages/sample_request_helpers.py`

Mirrors `quotation_helpers.py`, minus all totals/pricing math:

- `_next_sample_request_number(conn, year) -> str` — atomic counter upsert, called only inside `submit_sample_request`'s transaction.
- Read helpers: `_load_sample_request_header`, `_load_sample_request_lines`, `_load_status_events`, `_load_revisions`, `_load_revision_lines`.
- `render_sample_request_detail(sample_request_id)` — shared detail view (header, lines, status timeline, revision diff) used by all three pages, same pattern as `render_quotation_detail`.
- `render_sample_request_list(...)` — paginated/searchable/status-tabbed list, adapted from `render_quotation_list`.
- `_require_role(actor_uid, allowed_roles) -> str` — data-layer role re-check, identical to quotations'.
- `_odoo_reference_exists(ref) -> bool` — pre-check before enabling Mark Done, same as quotations.
- **Guarded transition functions** (single `engine.begin()` block, guarded `UPDATE ... WHERE ... RETURNING`, `rowcount==0` → `(False, "already resolved elsewhere, refresh")`, notification call in the same transaction):
  - `submit_sample_request(header, lines, actor_uid)` — assigns `request_number`, inserts header (`IN_REVIEW`, `version=0`), lines, revision #1 + revision lines, `SUBMITTED` event, `notify_role(["sales manager","admin"], ...)`.
  - `resubmit_sample_request(sample_request_id, header, lines, actor_uid, expected_version)` — guard `status='EDIT_REQUESTED' AND version=:expected_version AND rep_user_id=:actor_uid`, replaces lines, new revision, `RESUBMITTED` event, notifies `sales manager`/`admin`.
  - `manager_approve(sample_request_id, manager_uid)` — guard `status='IN_REVIEW' AND rep_user_id != :manager_uid` (self-review block, `admin` exempt) → `APPROVED`; notifies rep + `sales coordinator`/`admin`.
  - `manager_reject(sample_request_id, manager_uid, reason)` — same guard → `REJECTED`; notifies rep. Reason required.
  - `manager_request_edit(sample_request_id, manager_uid, comment)` — same guard → `EDIT_REQUESTED`; notifies rep. Comment required.
  - `manager_return_for_revision(sample_request_id, manager_uid, reason)` — guard `status='APPROVED' AND rep_user_id != :manager_uid` → `EDIT_REQUESTED`; notifies rep. Removes it from the coordinator's queue automatically.
  - `withdraw_sample_request(sample_request_id, rep_uid, reason)` — guard `status IN ('IN_REVIEW','EDIT_REQUESTED') AND rep_user_id=:rep_uid` → `WITHDRAWN`. No notification (matches quotations' `withdraw_quotation`).
  - `coordinator_mark_done(sample_request_id, coordinator_uid, odoo_reference, note)` — `_require_role(coordinator_uid, {"sales coordinator","admin"})`, guard `status='APPROVED'` → `DONE`; blank `odoo_reference` normalized to `NULL`; notifies rep + manager.
- **`generate_sample_pick_sheet(sample_request_id) -> bytes`** — the warehouse export (new, no quotation equivalent). Builds a fresh `.xlsx` via `openpyxl` (not a fill of the legacy template file): one sheet, header rows (Request No, Date, Customer), then one row **per physical unit** — for each line, `quantity` rows with a `"k of N"` unit label — columns `SI.NO, Model No, Item Description, Unit (k of N), Delivery Date, Serial/Batch Number (blank), Warehouse Name (blank), Warehouse Location (blank)`. Mirrors the legacy Warehouse sheet minus `Type`, `Old/New`, `Expected Receiving Date` (all dropped per the locked decisions above). Callable whenever status is `APPROVED` or `DONE` (so it can be regenerated/reprinted if the first copy is lost).
- **Manager insights functions** (new):
  ```python
  def get_rep_sample_stats(rep_user_id: int) -> dict:
      # all_time_qty, this_month_qty (both DONE-only, SUM(sample_request_lines.quantity)),
      # recent: last 5 DONE requests (request_number, coordinator_done_at, customer_name, item_summary, total_qty)
  ```
  ```python
  def get_customer_sample_stats(customer_id: int) -> dict:
      # same shape, but scoped to customer_id across ALL reps (no rep filter) —
      # deliberately unscoped by rep so a manager can catch two different reps
      # both sending samples to the same account
  ```
  Both are plain `query_df`/`query_scalar` calls (`db_ops.py`) — `status='DONE'`, `this_month` = `coordinator_done_at >= date_trunc('month', CURRENT_DATE)`, `all_time` = no date filter. No caching (review volume is low); zero-history rep/customer just returns zeros + an empty recent list, rendered as an empty-state message, not an error.

#### `app_pages/sample_request.py`

Rep-facing. Role-gated to `rep`, `sales manager`, `biomedical manager`, `admin` (same as Quotations — these roles already submit their own field records elsewhere in the app). Two tabs via `st.radio(horizontal=True)` (not `st.tabs()` — resets on rerun, documented gotcha already noted in `admin_change_requests.py`):
- **"New Sample Request"** — customer picker (reuse `widgets.py::customer_quick_find_module`/`customer_cascading_selectors`), up to 50 line-item rows (product picker from `items`, quantity, optional per-line delivery date), remarks, Submit → `submit_sample_request`.
- **"My Sample Requests"** — `WHERE rep_user_id = :uid` (or unfiltered for `admin`), grouped by status via `render_sample_request_list`. `EDIT_REQUESTED` rows show the manager's comment + **Edit & Resubmit** (prefills from latest revision) + **Withdraw**; `IN_REVIEW` rows show **Withdraw** only (mandatory reason + confirm-checkbox UX, same as quotations); terminal statuses render read-only.

#### `app_pages/sample_request_review.py`

Sales-manager-facing. Role-gated to `sales manager`, `admin`. Two sections:
- **Pending queue** (`status='IN_REVIEW' AND rep_user_id != :manager_uid` for non-admins) — before the Approve/Reject/Request-Edit buttons, render the **insights panel**: two `st.columns(2)` blocks (This Rep / This Customer), each with `st.metric("All-Time Units", ...)` + `st.metric("This Month", ...)` and an `st.expander("Recent Requests")` table. Then Approve (+optional comment) / Reject (+required reason) / Request Edit (+required comment).
- **Approved queue** (`status='APPROVED' AND rep_user_id != :manager_uid`) — read-only, with **Return to Rep for Revision** (mandatory reason, confirm-checkbox).

#### `app_pages/sample_request_handoff.py`

Sales-coordinator-facing. Role-gated to `sales coordinator`, `admin`. Approved queue (`status='APPROVED'`), shared read-only detail view, a **"Download Warehouse Pick Sheet"** `st.download_button` (calls `generate_sample_pick_sheet`, enabled for `APPROVED`/`DONE`), and the **Mark Done** form: Odoo reference (`st.text_input`, blank → `NULL`) + optional note. `_odoo_reference_exists()` checked on every rerun; if it matches, Mark Done is disabled with an `st.error` naming the conflicting request (hard block, not a dismissible warning — same as quotations).

## Workflow / state machine

Identical shape to Quotations:
```
Rep submits ──► [IN_REVIEW] ──┬─► manager_approve ──► [APPROVED] ──┬─► coordinator_mark_done ──► [DONE]  (terminal)
                     │        │                            │
                     │        ├─► manager_reject ──► [REJECTED]  (terminal)
                     │        │
                     │        ├─► manager_request_edit ──► [EDIT_REQUESTED]
                     │        │                                │
                     │        │                    rep resubmit_sample_request
                     │        │                                │
                     │        │                                ▼
                     │        └────────────────────────── back to [IN_REVIEW]  (loops indefinitely)
                     │                                          ▲
                     │                    manager_return_for_revision (from [APPROVED])
                     │
                     ├─► rep withdraw_sample_request (from IN_REVIEW) ──► [WITHDRAWN]  (terminal)
                     └─► rep withdraw_sample_request (from EDIT_REQUESTED) ──► [WITHDRAWN]  (terminal)
```

| Transition | Triggered by | Guard clause |
|---|---|---|
| `IN_REVIEW → APPROVED` | sales manager / admin | `status='IN_REVIEW' AND rep_user_id != :actor_uid` |
| `IN_REVIEW → REJECTED` | sales manager / admin | `status='IN_REVIEW' AND rep_user_id != :actor_uid` |
| `IN_REVIEW → EDIT_REQUESTED` | sales manager / admin | `status='IN_REVIEW' AND rep_user_id != :actor_uid` |
| `EDIT_REQUESTED → IN_REVIEW` | owning rep (resubmit) | `status='EDIT_REQUESTED' AND version=:expected_version AND rep_user_id=:actor_uid` |
| `APPROVED → DONE` | sales coordinator / admin | `status='APPROVED'` |
| `IN_REVIEW → WITHDRAWN` | owning rep | `status='IN_REVIEW' AND rep_user_id=:actor_uid` |
| `EDIT_REQUESTED → WITHDRAWN` | owning rep | `status='EDIT_REQUESTED' AND rep_user_id=:actor_uid` |
| `APPROVED → EDIT_REQUESTED` | sales manager / admin | `status='APPROVED' AND rep_user_id != :actor_uid` |

`admin` is exempt from every `rep_user_id != :actor_uid` clause (same short-circuit as `_require_role` in quotations).

## Do-not-break

Only additive edits to `app_v11.py`/`ui.py` (nav wiring, same pattern as every prior page addition). No edits to any `quotation_*.py` file, `admin_change_requests.py`, `change_request*.py`, or `app_settings.py`. No `admin_users.py` change needed — `sales coordinator` already exists on `users.role`.

Two recurring bug classes to guard against (both previously fixed elsewhere in this codebase):
1. **NaN/NULL truthiness** on nullable columns (`manager_comment`, `coordinator_note`, `odoo_reference`, `withdrawal_reason`, `delivery_date`) — route through `_norm()`/`_sql_val()`.
2. Streamlit `st.tabs()` resetting on rerun — use `st.radio(horizontal=True)` for the New/My-Requests toggle, matching every other module in this app.

## Verification

## Decision Log

| Decision | Alternatives considered | Why chosen |
|---|---|---|
| Serial/batch/warehouse-location stays off the DB entirely; app only exports a blank pick sheet | (a) Structured per-unit capture in-app after approval; (b) hybrid export + re-upload of the filled sheet as an attachment | (a) adds a whole warehouse-inventory data model for a workflow that already works fine on paper — it's what made the original design feel "messy." (b) adds file-storage/upload complexity for data nobody downstream actually queries. Plain export keeps the app's scope to the request lifecycle, matching what Quotations already does for its Odoo handoff. |
| No new "warehouse staff" role | Give warehouse staff their own login to enter data directly | No structured in-app data means there's nothing for a separate role to enter — the coordinator already does this step manually today. |
| Excel-only pick sheet (no PDF) | Excel + PDF; Excel with round-trip re-upload | Excel is what warehouse staff already use and can write directly into cells; PDF adds no capability here (no round-trip needed since we chose "simple reference only"). |
| "Type" (Sample/Demo) omitted entirely, not just hidden | Keep a hidden `request_type` column defaulted to `'SAMPLE'` for future-proofing | Demo will be a genuinely separate module with a different workflow (rotation/return tracking) per the user's stated plan — forcing it into this table now would be speculative design for a feature whose shape isn't decided yet (YAGNI). |
| Expected-return-date field dropped entirely | Keep as an optional per-line field | Samples aren't returned in the normal case; an optional-but-unused field is clutter without a concrete need driving it. |
| Insights panel counts only `DONE` (fulfilled) requests | Count `APPROVED`+`DONE`; count all non-terminal-negative statuses (include pipeline) | Manager wants to know what's actually gone out historically to judge a new request, not what's still in flight — fulfilled-only avoids double-counting/inflating a rep's history with requests that might still get rejected or stuck. |
| Insights metric is total unit quantity, not request count | Request count; both shown | Unit quantity is the more meaningful signal for judging sample "spend"/exposure — 1 request for 20 units matters more than 5 requests for 1 unit each. |
| Customer insight scoped across all reps | Scoped to the current rep + customer pair only | Explicitly catches the cross-rep duplication case the user raised ("the samples that this customer took too") — a narrower scope would hide exactly the pattern a manager most needs to see. |
| Own tables (`sample_request_*`) rather than reusing `quotation_*` tables | Reuse quotation tables with a type discriminator column | Field sets diverge materially (no pricing on samples, has per-line delivery dates, needs pick-sheet export) — same reasoning Quotations itself used to justify not reusing `request_changes`. |
