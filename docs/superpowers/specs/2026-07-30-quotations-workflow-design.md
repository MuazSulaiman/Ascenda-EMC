# Quotations Workflow — Design Spec (amended)

**Status:** Approved for implementation. This supersedes `docs/Quotations_Workflow_Plan.md` where the two differ — the four amendments below were decided with the user after independent verification of the original plan against the live codebase. Everything in the original plan that isn't touched by an amendment still applies.

## Amendments vs. the original plan (`docs/Quotations_Workflow_Plan.md`)

1. **No Postgres ENUM type.** Use `TEXT NOT NULL CHECK (col IN (...))` for `quotation_requests.status` and `quotation_status_events.from_status`/`to_status`, matching the newer `migrations/targets_schema.sql` convention (`target_year.status`) rather than the older `asc_request_status`-style enum. This avoids the `AUTOCOMMIT`-isolation dance `db.py` needs for `ALTER TYPE ... ADD VALUE`, which `docs/supabase_migration_assessment.md` already flags as incompatible with PgBouncer transaction-mode pooling (a migration path this team is evaluating).
2. **No `manufacturer` field anywhere.** Not on `quotation_requests`, not on `quotation_revisions`, no dropdown, no `MANUFACTURER_OPTIONS` constant. Confirmed in schema: `items.business_line_id → business_lines.supplier` already carries this per line item — a header-level free-text manufacturer field would be redundant, driftable data entry. If a manufacturer/supplier label is useful in the read-only detail view, join `business_lines.supplier` through `items.business_line_id` per line — do not store it.
3. **Managers/biomedical managers may submit their own quotations** (self-review guard blocks them approving their own) — unchanged from the original plan.
4. **Ship unscoped manager visibility** (any sales manager/admin sees any pending quotation except their own) — unchanged from the original plan.

## Schema (final, as amended)

All of the below goes into `init_db_v11.py`'s `SCHEMA_SQL` block (fresh-DB path) **and** `migrations/quotations_schema.sql` (loaded by `db.py::_run_migrations()` at every startup, same precedent as `migrations/targets_schema.sql`). Creation order: `quotation_requests` → `quotation_lines` → `quotation_revisions` → `quotation_revision_lines` → `quotation_status_events` → `quotation_number_counters` → indexes → `users.role` CHECK migration.

### `quotation_requests` (header)

```sql
CREATE TABLE IF NOT EXISTS quotation_requests (
    quotation_id      BIGINT  GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    quotation_number  TEXT    NOT NULL UNIQUE,
    customer_id       INTEGER NOT NULL REFERENCES customers(customer_id),
    rep_user_id       INTEGER NOT NULL REFERENCES users(user_id),
    request_source    TEXT    NOT NULL CHECK (request_source IN (
                           'Purchasing Dept.', 'Procurement Dept.', 'Sales Dept.', 'Direct Request'
                       )),
    quotation_date    DATE    NOT NULL DEFAULT CURRENT_DATE,
    vat_rate          NUMERIC(5,2) NOT NULL DEFAULT 15.00 CHECK (vat_rate BETWEEN 0 AND 100),

    remarks           TEXT,
    validity_days     INTEGER CHECK (validity_days IN (30, 60, 90, 180, 365)),
    delivery_terms    TEXT CHECK (delivery_terms IN (
                           'Immediate', '15 Days', '30 Days', '45 Days',
                           '60 Days', '90 Days', '120 Days'
                       )),
    payment_terms     TEXT CHECK (payment_terms IN (
                           'Cash in Advance', 'Cash on Delivery', '15 Days', '30 Days',
                           '60 Days', '90 Days', '120 Days', 'As per Agreed Policy'
                       )),

    status    TEXT NOT NULL DEFAULT 'IN_REVIEW' CHECK (status IN (
                   'IN_REVIEW', 'EDIT_REQUESTED', 'REJECTED', 'APPROVED', 'DONE', 'WITHDRAWN'
               )),
    version   INTEGER NOT NULL DEFAULT 0,

    submitted_at  TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    submitted_by  INTEGER NOT NULL REFERENCES users(user_id),

    manager_user_id     INTEGER REFERENCES users(user_id),
    manager_decided_at  TIMESTAMPTZ,
    manager_comment     TEXT,

    coordinator_user_id  INTEGER REFERENCES users(user_id),
    coordinator_done_at  TIMESTAMPTZ,
    coordinator_note     TEXT,
    odoo_reference        TEXT,

    withdrawn_at       TIMESTAMPTZ,
    withdrawn_by        INTEGER REFERENCES users(user_id),
    withdrawal_reason    TEXT,

    is_deleted   BOOLEAN NOT NULL DEFAULT FALSE,
    deleted_at    TIMESTAMPTZ,
    deleted_by     INTEGER REFERENCES users(user_id)
);
```
`request_source` is the business dropdown (not `requested_by`, which reads as ambiguous with `submitted_by`/`rep_user_id`). `is_deleted`/`deleted_at`/`deleted_by` are an admin-only hard data-repair escape hatch, never used by the normal rep-facing cancel flow — that's `WITHDRAWN` (real workflow history, not deletion). `odoo_reference`: blank input normalized to `NULL` before it reaches SQL, never `''`.

### `quotation_lines`

```sql
CREATE TABLE IF NOT EXISTS quotation_lines (
    line_id       BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    quotation_id  BIGINT NOT NULL REFERENCES quotation_requests(quotation_id) ON DELETE CASCADE,
    line_no       SMALLINT NOT NULL CHECK (line_no BETWEEN 1 AND 14),
    product_id    TEXT NOT NULL REFERENCES items(product_id),
    quantity      NUMERIC(14,3) NOT NULL CHECK (quantity > 0),
    unit_price    NUMERIC(14,2) NOT NULL CHECK (unit_price >= 0),
    discount_pct  NUMERIC(5,2)  NOT NULL DEFAULT 0 CHECK (discount_pct BETWEEN 0 AND 100),
    created_at    TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    UNIQUE (quotation_id, line_no)
);
```
14-line cap matches the Excel template's fixed row range (`E16:E29`). `NUMERIC(14,3)` matches the template's "must be a positive decimal" validation (not integer-only), and no per-product whole-units rule exists on `items`. `resubmit_quotation` deletes and re-inserts the full line set on every resubmit (simplest correct approach for ≤14 rows) — no `updated_at`, nothing is ever updated in place. Line/VAT/grand totals are **computed on read**, never stored on the live header/lines: `qty × price × (1 − discount%)` per line, VAT on the summed subtotal, all via Python `Decimal` quantized to 2dp with `ROUND_HALF_UP`, in one shared function used everywhere (`compute_line_total`/`compute_header_totals` in `quotation_helpers.py`).

### `quotation_revisions` / `quotation_revision_lines` — immutable audit snapshots

Full snapshot taken on every first submission and every resubmission only (never on withdraw/approve/reject/return-for-revision/mark-done — those don't change document content):

```sql
CREATE TABLE IF NOT EXISTS quotation_revisions (
    revision_id     BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    quotation_id    BIGINT NOT NULL REFERENCES quotation_requests(quotation_id) ON DELETE CASCADE,
    revision_no     SMALLINT NOT NULL,
    created_at      TIMESTAMPTZ NOT NULL DEFAULT NOW(),
    created_by      INTEGER NOT NULL REFERENCES users(user_id),

    customer_id     INTEGER NOT NULL REFERENCES customers(customer_id),
    request_source  TEXT NOT NULL,
    quotation_date  DATE NOT NULL,
    vat_rate        NUMERIC(5,2) NOT NULL,
    remarks         TEXT,
    validity_days   INTEGER,
    delivery_terms  TEXT,
    payment_terms   TEXT,

    subtotal        NUMERIC(16,2) NOT NULL,
    vat_amount      NUMERIC(16,2) NOT NULL,
    grand_total     NUMERIC(16,2) NOT NULL,

    UNIQUE (quotation_id, revision_no)
);

CREATE TABLE IF NOT EXISTS quotation_revision_lines (
    revision_line_id         BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    revision_id              BIGINT NOT NULL REFERENCES quotation_revisions(revision_id) ON DELETE CASCADE,
    line_no                  SMALLINT NOT NULL,
    product_id               TEXT NOT NULL REFERENCES items(product_id),
    article_number_snapshot  TEXT,
    description_snapshot     TEXT,
    quantity                 NUMERIC(14,3) NOT NULL,
    unit_price                NUMERIC(14,2) NOT NULL,
    discount_pct               NUMERIC(5,2) NOT NULL,
    line_total                  NUMERIC(16,2) NOT NULL
);
```
`article_number_snapshot`/`description_snapshot` freeze `items.article_number`/`items.description` at snapshot time — item master data can change later and must not silently alter an old revision's meaning. Revisions/revision-lines are **never updated or deleted** by application code.

**Revision numbering is derived from `version`, never `MAX(revision_no)+1`** (races under concurrent resubmits): `submit_quotation` inserts header with `version=0`, writes `revision_no=1`, in one transaction. `resubmit_quotation`'s guarded `UPDATE ... SET version = version + 1 WHERE quotation_id=:qid AND status='EDIT_REQUESTED' AND version=:expected_version RETURNING version` returns the new version atomically (row-locked by the UPDATE itself), and the revision written in the same transaction uses `revision_no = <returned version> + 1`. `UNIQUE (quotation_id, revision_no)` is a DB-level backstop, not the primary mechanism.

`quotation_helpers.py` gets `render_revision_diff(revision_a, revision_b)` — header-field-by-field and line-by-line comparison, same visual idiom as `ui.py::compare_row` / `admin_change_requests.py::_render_diff_table`.

### `quotation_status_events`

```sql
CREATE TABLE IF NOT EXISTS quotation_status_events (
    event_id        BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    quotation_id    BIGINT NOT NULL REFERENCES quotation_requests(quotation_id) ON DELETE CASCADE,
    event_type      TEXT NOT NULL CHECK (event_type IN (
                         'SUBMITTED', 'RESUBMITTED', 'EDIT_REQUESTED', 'APPROVED',
                         'REJECTED', 'WITHDRAWN', 'RETURNED_FOR_REVISION', 'MARKED_DONE'
                     )),
    actor_user_id   INTEGER NOT NULL REFERENCES users(user_id),
    from_status     TEXT,
    to_status       TEXT NOT NULL,
    comment         TEXT,
    revision_id     BIGINT REFERENCES quotation_revisions(revision_id),
    at_utc          TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
```
`revision_id` set only for `SUBMITTED`/`RESUBMITTED` (to the exact revision row created in that same transaction), `NULL` for every other event type.

### `quotation_number_counters`

```sql
CREATE TABLE IF NOT EXISTS quotation_number_counters (
    year     INTEGER PRIMARY KEY,
    last_seq INTEGER NOT NULL DEFAULT 0
);
```
Incremented atomically inside `submit_quotation`'s transaction:
```sql
INSERT INTO quotation_number_counters (year, last_seq) VALUES (:yr, 1)
ON CONFLICT (year) DO UPDATE SET last_seq = quotation_number_counters.last_seq + 1
RETURNING last_seq;
```
Formatted as `f"QT-{year}-{seq:06d}"`. Assigned once, at first submission only.

### Duplicate Odoo reference — hard block

```sql
CREATE UNIQUE INDEX IF NOT EXISTS idx_qr_odoo_ref_unique
    ON quotation_requests (odoo_reference) WHERE odoo_reference IS NOT NULL;
```
Primary defense is in the UI layer: before "Mark Done" is clickable, `quotation_helpers._odoo_reference_exists(ref) -> bool` runs (`SELECT 1 FROM quotation_requests WHERE odoo_reference = :ref`). The unique index is the backstop for the true concurrent-race case, caught via the same `try/except` idiom `_apply_changes` already uses.

### Role change — add `'sales coordinator'`

`init_db_v11.py`'s `users` table CHECK gains `'sales coordinator'`:
```sql
role TEXT NOT NULL CHECK (role IN (
    'admin', 'rep', 'maintenance', 'supervisor',
    'sales manager', 'biomedical manager', 'sales coordinator'
))
```
For existing databases, `db.py::_run_migrations()` needs an idempotent migration since there's no prior `ALTER TABLE users DROP/ADD CONSTRAINT` precedent in this codebase to copy and the constraint has no explicit name (Postgres auto-names it). Use a `DO $$ ... $$` block that looks up the actual CHECK constraint on `users` mentioning `role` via `pg_constraint`/`pg_get_constraintdef`, and only replaces it if `'sales coordinator'` isn't already present (idempotent, no-ops on repeat runs and on fresh DBs that already have it via `init_db_v11.py`):
```sql
DO $$
DECLARE
    _conname TEXT;
    _condef  TEXT;
BEGIN
    SELECT con.conname, pg_get_constraintdef(con.oid) INTO _conname, _condef
    FROM pg_constraint con
    JOIN pg_class rel ON rel.oid = con.conrelid
    WHERE rel.relname = 'users'
      AND con.contype = 'c'
      AND pg_get_constraintdef(con.oid) ILIKE '%role%'
    LIMIT 1;

    IF _conname IS NOT NULL AND _condef NOT ILIKE '%sales coordinator%' THEN
        EXECUTE format('ALTER TABLE users DROP CONSTRAINT %I', _conname);
        ALTER TABLE users ADD CONSTRAINT users_role_check CHECK (role IN (
            'admin', 'rep', 'maintenance', 'supervisor',
            'sales manager', 'biomedical manager', 'sales coordinator'
        ));
    END IF;
END $$;
```
Also add `"sales coordinator"` to the two hardcoded role-dropdown lists in `app_pages/admin_users.py` — confirmed actual lists are `["", "rep", "admin", "sales manager", "biomedical manager", "maintenance"]` at line ~241 (Add User form `role` selectbox) and line ~445 (`role_opts` in the Edit Role/Region/BU popover). Preserve `"maintenance"` — just append `"sales coordinator"`. Do **not** touch `role_objectives`'s CHECK list (visit-objective visibility only; coordinators don't submit visits).

### `app_pages/quotation_helpers.py`

Mirrors `change_request_helpers.py`. Reuses (imports, does not reimplement): `_norm`, `_sql_val` (from `change_request_helpers.py`), the BU→Category→Business Line→Product cascading loaders, and `widgets.py::customer_quick_find_module`/`customer_cascading_selectors`. New:

- `_next_quotation_number(conn, year) -> str` — the atomic counter upsert above, called only inside `submit_quotation`'s transaction.
- Read helpers: `_load_quotation_header`, `_load_quotation_lines`, `_load_status_events`, `_load_revisions`, `_load_revision_lines`.
- `render_revision_diff(revision_a, revision_b)` and `render_quotation_detail(quotation_id)` — shared view used by all three pages.
- Fixed dropdown-option constants: `REQUEST_SOURCE_OPTIONS`, `VALIDITY_OPTIONS`, `DELIVERY_OPTIONS`, `PAYMENT_TERMS_OPTIONS` (one Python source list per dropdown, imported by all three pages, so CHECK-constraint values and `st.selectbox` options can't drift). No `MANUFACTURER_OPTIONS` — that field doesn't exist.
- `_status_badge_variant(status)` mapping, including `WITHDRAWN`.
- `_odoo_reference_exists(ref) -> bool`.
- `_require_role(actor_uid: int, allowed_roles: set[str]) -> str` — data-layer authorization guard: every transition function re-queries the actor's *current* role from the DB (`SELECT role FROM users WHERE user_id=:uid`) rather than trusting `st.session_state["user"]["role"]`. Defense-in-depth underneath the existing `PAGE_ROLES`/`sidebar_nav()` page-level gate.
- **Guarded status-transition functions**, all following `admin_change_requests.py::_apply_changes`/`_reject_request`'s exact idiom — single `engine.begin()` block, `UPDATE ... WHERE quotation_id = :qid AND status = '<expected>'`, `rowcount == 0` → `(False, "already resolved elsewhere, refresh")`, plus `_require_role` as the first line of every manager/coordinator function:
  - `submit_quotation(header, lines, actor_uid)` — one transaction: assign `quotation_number` via `_next_quotation_number`, INSERT header (`status='IN_REVIEW'`, `version=0`), INSERT lines, INSERT revision `#1` + revision lines (via `compute_header_totals`), INSERT a `SUBMITTED` event with `revision_id` set to the new revision. Pure insert, no status guard needed.
  - `resubmit_quotation(quotation_id, header, lines, actor_uid, expected_version)` — guard: `WHERE status='EDIT_REQUESTED' AND version=:expected_version AND rep_user_id=:actor_uid`, using `RETURNING version`. Same transaction: replace `quotation_lines`, set `status='IN_REVIEW'`, insert `quotation_revisions` with `revision_no = <returned version> + 1`, insert `RESUBMITTED` event pointing at that revision. `rowcount==0` rolls back everything.
  - `manager_approve(quotation_id, manager_uid)` — `_require_role(manager_uid, {"sales manager", "admin"})`, then `WHERE status='IN_REVIEW' AND rep_user_id != :manager_uid` → `APPROVED`; `APPROVED` event. `admin` is exempt from the self-review clause (implemented inside `_require_role`/the calling function short-circuiting it for `admin` actors).
  - `manager_reject(quotation_id, manager_uid, reason)` — same role+self-review guard, `WHERE status='IN_REVIEW' AND rep_user_id != :manager_uid` → `REJECTED`, `manager_comment=reason`; `REJECTED` event. Reason required at call site.
  - `manager_request_edit(quotation_id, manager_uid, comment)` — same guard → `EDIT_REQUESTED`, `manager_comment=comment`; `EDIT_REQUESTED` event. Comment required.
  - `manager_return_for_revision(quotation_id, manager_uid, reason)` — same guard, `WHERE status='APPROVED' AND rep_user_id != :manager_uid` → `EDIT_REQUESTED`, `manager_comment=reason`; `RETURNED_FOR_REVISION` event. Automatically drops the row from the coordinator's `status='APPROVED'` queue.
  - `withdraw_quotation(quotation_id, rep_uid, reason)` — `WHERE status IN ('IN_REVIEW','EDIT_REQUESTED') AND rep_user_id=:rep_uid` → `WITHDRAWN`, sets `withdrawn_at`/`withdrawn_by`/`withdrawal_reason`; `WITHDRAWN` event. Reason required.
  - `coordinator_mark_done(quotation_id, coordinator_uid, odoo_reference, note)` — `_require_role(coordinator_uid, {"sales coordinator", "admin"})`, `WHERE status='APPROVED'` → `DONE`; normalizes blank `odoo_reference` to `NULL`; `MARKED_DONE` event. Re-checks `_odoo_reference_exists()` as the final backstop even though the caller should have already checked it.

## Workflow / state machine

```
   Rep submits ──► [IN_REVIEW] ──┬─► manager_approve ──► [APPROVED] ──┬─► coordinator_mark_done ──► [DONE]  (terminal)
                        │        │                            │
                        │        ├─► manager_reject ──► [REJECTED]  (terminal)
                        │        │
                        │        ├─► manager_request_edit ──► [EDIT_REQUESTED]
                        │        │                                │
                        │        │                    rep resubmit_quotation
                        │        │                                │
                        │        │                                ▼
                        │        └────────────────────────── back to [IN_REVIEW]  (loops indefinitely)
                        │                                          ▲
                        │                    manager_return_for_revision (from [APPROVED])
                        │
                        ├─► rep withdraw_quotation (from IN_REVIEW) ──► [WITHDRAWN]  (terminal)
                        └─► rep withdraw_quotation (from EDIT_REQUESTED) ──► [WITHDRAWN]  (terminal)
```
Terminal states: `REJECTED`, `DONE`, `WITHDRAWN`. A `WITHDRAWN` row can never be resubmitted (falls out of `resubmit_quotation`'s `status='EDIT_REQUESTED'` guard).

**Guard/race-condition table** (every transition: single `UPDATE ... WHERE quotation_id=:qid AND <guard>` inside one `engine.begin()` block; `rowcount==0` always means "someone else already changed this, refresh"; manager/coordinator functions additionally call `_require_role` before the transaction):

| Transition | Triggered by | Guard clause |
|---|---|---|
| `IN_REVIEW → APPROVED` | sales manager / admin | `status='IN_REVIEW' AND rep_user_id != :actor_uid` |
| `IN_REVIEW → REJECTED` | sales manager / admin | `status='IN_REVIEW' AND rep_user_id != :actor_uid` |
| `IN_REVIEW → EDIT_REQUESTED` | sales manager / admin | `status='IN_REVIEW' AND rep_user_id != :actor_uid` |
| `EDIT_REQUESTED → IN_REVIEW` | owning rep (resubmit) | `status='EDIT_REQUESTED' AND version=:expected_version AND rep_user_id=:actor_uid` |
| `APPROVED → DONE` | sales coordinator / admin | `status='APPROVED'` |
| `IN_REVIEW → WITHDRAWN` | owning rep | `status='IN_REVIEW' AND rep_user_id=:actor_uid` |
| `EDIT_REQUESTED → WITHDRAWN` | owning rep | `status='EDIT_REQUESTED' AND rep_user_id=:actor_uid` |
| `APPROVED → EDIT_REQUESTED` | sales manager / admin | `status='APPROVED' AND rep_user_id != :actor_uid` |

`admin` is exempt from the `rep_user_id != :actor_uid` self-review clause everywhere, implemented by short-circuiting the self-review clause specifically for `admin` actors (not by omitting the clause generally).

1. **NaN/NULL truthiness** — any DataFrame value read into a conditional or SQL parameter (especially nullable `manager_comment`/`coordinator_note`/`odoo_reference`/`withdrawal_reason` columns) must go through `_norm()`/`_sql_val()` (imported from `change_request_helpers.py`), per commits `1d9f780`/`8a16b3c`.
2. **Float rounding in money math** — `Decimal` everywhere for totals pre-empts this; no `float()` casts anywhere in `compute_line_total`/`compute_header_totals` or the revision-snapshot writer.

## Verification

**Manual walkthrough**: create test `rep`/`sales manager`/`sales coordinator` users; submit a quotation as the rep (confirm a `QT-<year>-<seq>` number is assigned and a revision #1 snapshot exists, linked from the `SUBMITTED` event's `revision_id`); as manager, request an edit, confirm the rep sees the comment and can either resubmit (producing revision #2, confirm revision-diff view shows what changed) or withdraw (mandatory-reason + confirmation-warning UX; row disappears from manager's pending queue and becomes read-only for the rep); approve a second test quotation, then as manager use **Return to Rep for Revision** and confirm it leaves the coordinator's queue and re-enters the edit loop; as a *different* sales-manager account, confirm you cannot approve/reject/request-edit a quotation the first sales-manager account submitted for themselves; as coordinator, mark a genuinely-approved quotation Done with a fabricated Odoo reference, then attempt to reuse that reference on a different quotation and confirm Mark Done is **disabled** with an error naming the conflict; as admin, confirm full oversight (including approving a manager's self-submitted quotation) and confirm a `rep` account is blocked from `Review Quotations`/`Quotation Handoff` both via sidebar and direct `?page=` URL manipulation.

**Automated tests** — `tests/test_quotation_workflow_race.py` (self-cleaning fixtures against the live DB, following `tests/test_admin_change_requests_race.py`'s structure):
- `test_approve_after_reject_is_noop`, `test_reject_twice_is_noop`, `test_mark_done_before_approve_is_noop`.
- `test_resubmit_stale_version_is_noop` — resubmit once (bumps version), then attempt a second resubmit using the stale captured version; must fail even though status alone would allow it.
- `test_withdraw_while_in_review` / `test_withdraw_while_edit_requested` — both succeed.
- `test_withdraw_after_approve_is_blocked` — guard doesn't match `APPROVED`, returns `(False, ...)`.
- `test_withdraw_by_another_rep_is_blocked` — guard's `rep_user_id` clause rejects it.
- `test_manager_action_after_withdrawal_is_noop` — approve/reject/request-edit all fail once `WITHDRAWN`.
- `test_resubmit_after_withdrawal_is_blocked` — `status='EDIT_REQUESTED'` guard naturally rejects a `WITHDRAWN` row.
- `test_manager_cannot_approve_own_submission` — a sales-manager account submits, then attempts to approve/reject/request-edit its own request; all blocked; an admin or a *different* sales manager succeeds.
- `test_return_for_revision_from_approved` — succeeds, row leaves the `APPROVED` (coordinator) queue.
- `test_old_revisions_remain_unchanged` — create revision #1, resubmit to create #2, assert #1's stored rows are byte-identical to what was captured before the resubmit.
- `test_failed_resubmit_does_not_partially_update` — force a failure inside `resubmit_quotation` and assert lines, version, status, and revision count are all unchanged afterward.
- `test_duplicate_odoo_reference_is_blocked` — mark one quotation Done with a reference, attempt to mark a second Done with the same reference; assert rejected at both the `_odoo_reference_exists()` pre-check level and, bypassing that check, at the unique-index level.

`tests/test_quotation_totals.py` (pure function tests, no DB dependency) — `compute_line_total`/`compute_header_totals` against hand-computed cases including 0% and 100% discount, and a rounding case chosen to distinguish `Decimal` quantization from naive float arithmetic across 14 lines.
